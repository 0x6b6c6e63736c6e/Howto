BAŞLANGIÇ REHBERİ

Git nedir?

Projenin değişiklik geçmişini kaydet.

Git, dosyalarındaki değişiklikleri kaydeden dağıtık bir sürüm kontrol sistemidir. Geçmişe bakabilir, ayrı bir dalda fikirlerini deneyebilir ve ekip arkadaşlarınla aynı proje üzerinde çalışabilirsin.

Bir değişiklik nasıl kaydedilir?

Önce dosyanı düzenle, sonra kayda girecek sürümü seç ve bir mesajla commit oluştur.

Proje dosyalarının düzenlediğin hâli.

git status
02

03

Depo geçmişi

Commit’lerin, yani projenin kaydedilmiş sürümlerinin geçmişi.

git commit
Git ve GitHub arasındaki fark

Git, bilgisayarında çalışan sürüm kontrol aracıdır. GitHub ise Git depolarını barındıran ve paylaşmanı sağlayan bir hizmettir. İlk commit için internete veya GitHub hesabına ihtiyacın yok.

ADIM ADIM

İlk deponu oluştur.

Boş bir klasörden başla ve ilk commit’ini terminalde gör.

  1. Git’i kur ve kontrol et

    Sistemine uygun yükleyiciyi resmî Git sitesinden edin. Windows’ta sonraki adımları Git Bash’te, macOS ve Linux’ta Terminal’de çalıştır.

    Komut bir sürüm numarası gösterirse Git kullanıma hazırdır. Örnekler için Git 2.28 veya üzerini kullan.

    Terminal
    git --version

  2. Depoyu başlat ve kimliğini ayarla

    Yeni bir klasör oluştur ve ana dalı main olarak başlat. Adı ve e-posta adresini kendi bilgilerinle değiştir. Bu ayarlar yalnızca bu depoya uygulanır ve commit’lerinde görünür.

    Terminal
    mkdir git-deneme
cd git-deneme
git init -b main
git config user.name "Ad Soyad"
git config user.email "ad@example.com"

  3. Bir dosya oluştur ve kaydet

    İlk komutu yeni deneme klasöründe çalıştır. git add, README’nin o anki sürümünü hazırlar. Commit’ten önce dosyayı tekrar düzenlersen yeni sürümü eklemek için git add komutunu yeniden çalıştır.

    Terminal
    printf '# Git Denemem\n' > README.md
git status --short
git add README.md
git diff --staged
git commit -m "İlk commit"

  4. İlk commit’ini gör

    İlk satırda kısa commit kimliğini ve İlk commit mesajını görürsün. İkinci komut çıktı vermezse çalışma klasöründe bekleyen değişiklik yoktur.

    Terminal
    git log --oneline
git status --short

İLK COMMIT’TEN SONRA

Dal aç, değişikliği incele ve birleştir.

İlk depoyu oluşturduğun git-deneme klasöründe devam et. Örnekte README dosyasına bir kullanım bölümü ekleyeceğiz.

  1. README için bir dal aç

    git switch -c bulunduğun commit’ten yeni bir dal oluşturur ve o dala geçer. git branch --show-current çıktısında readme-notlari görmelisin.

    Terminal
    git switch -c readme-notlari
git branch --show-current

  2. Dosyayı düzenle ve farkına bak

    >> var olan dosyanın sonuna ekler. İlk diff düzenlediğin satırları, ikinci diff commit için seçtiğin satırları gösterir. Eklenen satırlar + ile başlar.

    Terminal
    printf '\n## Kullanım\n' >> README.md
git diff -- README.md
git add README.md
git diff --staged -- README.md
git commit -m "README kullanım bölümünü ekle"

  3. Değişikliği ana dala al

    main dalına geçince README yeniden ilk kayıttaki içeriğini gösterir. Birleştirme tamamlanınca kullanım başlığı da görünür. Örnekte --no-ff kullanarak iki ebeveynli bir birleştirme commit’i oluşturuyoruz. İki dalın izini git log --graph çıktısında görebilirsin.

    Terminal
    git switch main
cat README.md
git merge --no-ff -m "README dalını birleştir" readme-notlari
cat README.md
git log --oneline --graph --all
Fast-forward ne demek?

main dalı ayrıldığın noktadan sonra ilerlemediyse Git, varsayılan davranışla main işaretçisini yeni commit’e taşıyabilir. Bu durumda geçmişe ayrıca bir birleştirme commit’i eklenmez.

Birleştirme çakışırsa ne yapacağım?

İki dal aynı satırı farklı biçimde düzenlediğinde Git, hangi içeriğin kalacağına karar vermeni isteyebilir. Dosyada <<<<<<<, ======= ve >>>>>>> işaretlerini bul. Kalmasını istediğin metni yaz ve işaretleri sil. Sonra dosyayı git add README.md ile çözülmüş olarak işaretle. git status başka çakışma göstermiyorsa git commit ile birleştirmeyi tamamla. Tamamlamadan vazgeçersen git merge --abort ile birleştirmeyi iptal edebilirsin.

DÜZELTME

Değişiklik hangi aşamada?

git status --short çıktısında ?? yeni dosyayı, ilk sütundaki M hazırlığa alınan değişikliği, ikinci sütundaki M çalışma klasöründeki değişikliği gösterir. Aynı dosya iki sütunda birden görünebilir.

git restore --staged README.md
Dosyayı bir sonraki commit’ten çıkarır ve çalışma klasöründeki düzenlemelerini korur.
git restore -- README.md
İzlenen dosyanın hazırlık alanındaki sürümünü çalışma klasörüne yazar. Hazırlığa alınmamış düzenlemeler silinir. Uygulamadan önce git diff -- README.md ile farkı gör.
git revert <commit-kimliği>
Verdiğin commit’in değişikliğini tersine çeviren yeni bir commit oluşturur. Paylaşılan dalda geçmişi koruyarak düzeltme yapmak için kullanabilirsin.
Küçük bir geri alma denemesi

Önceki dersi bitirdiysen main dalında geçici bir satır ekle ve ayrı bir commit oluştur. Ardından HEAD ile işaret edilen bu son commit’i geri al. Geçmişte iki yeni commit de görünür, README kullanım başlığını korur. Bu örnekte geri alınan commit geçici satırı ekleyen normal commit’tir.

Terminal
printf '\nGeçici not\n' >> README.md
git add README.md
git commit -m "Geçici notu ekle"
git revert --no-edit HEAD
git log -2 --oneline
cat README.md

PAYLAŞIM

Deponu paylaş ve güncel tut.

Uzak depo, ekibin ortak eriştiği Git deposudur. origin, bu bağlantı için yaygın kullanılan yerel addır.

  1. Boş bir uzak depoya bağlan

    GitHub veya GitLab’da yazma yetkin olan boş bir depo oluştur. README gibi başlangıç dosyaları eklemeden açarsan yerel geçmişini doğrudan gönderebilirsin. Aşağıdaki UZAK_DEPO_ADRESI metnini kendi HTTPS veya SSH adresinle değiştir.

    Terminal
    git remote add origin UZAK_DEPO_ADRESI
git remote -v
git push -u origin main

  2. Gelen değişiklikleri önce incele

    fetch yeni commit’leri indirir ve origin/main bilgisini günceller. Çalışma klasörü değişmez. Örnekteki log komutu, uzak dalda olup yerel main dalında bulunmayan commit’leri listeler.

    Terminal
    git switch main
git fetch origin
git log --oneline main..origin/main

  3. Yerel dalı güncelle

    git pull --ff-only gelen commit’leri indirir ve dal işaretçisini ileri taşıyabiliyorsa günceller. İki tarafta da farklı commit’ler varsa işlem durur. Ekipte kullandığınız birleştirme yöntemine karar vermek için önce iki dalın geçmişini incele.

    Terminal
    git pull --ff-only
Var olan bir projeye katılmak

Projeyi bilgisayarına ilk kez alıyorsan git clone DEPO_ADRESI kullan. Klonlama yeni bir klasör, yerel bir depo ve origin bağlantısı oluşturur.

Git komutları

Günlük iş akışında hangi komutu ne zaman kullanacağını gör.

git status -sb
Bulunduğun dalı ve dosyaların durumunu kısa biçimde gösterir.
git diff
İzlenen dosyalardaki henüz hazırlık alanına alınmamış değişiklikleri gösterir.
git diff --staged
Bir sonraki commit için hazırlanan değişiklikleri gösterir.
git log --oneline
Geçerli daldan erişilebilen commit’leri kısa kimlikleri ve mesajlarıyla listeler.
git switch -c yeni-dal
Bulunduğun commit’ten yeni bir dal oluşturur ve o dala geçer.
git clone <depo-url>
Mevcut bir depoyu geçmişiyle birlikte bilgisayarına kopyalar.

Sık sorulan sorular

Dal (branch) nedir?

Dal, bir commit’i işaret eden isimdir. Yeni commit oluşturdukça o dalın işaretçisi ilerler. Ayrı bir dalda çalışarak main dalının geçmişini doğrudan değiştirmeden yeni bir fikri deneyebilirsin.

Commit’lerim uzak depoda neden görünmüyor?

git commit yerel depoya kayıt yapar. Uzak depo bağlıysa ve yazma yetkin varsa git push -u origin main ile main dalını origin adlı uzak depoya gönderebilirsin. Bağlantıları git remote -v ile kontrol edebilirsin.

Git’in bazı dosyaları takip etmesini nasıl önlerim?

Örneğin .env dosyasını veya node_modules/ klasörünü, Git henüz takip etmeye başlamadan önce .gitignore dosyasına ayrı satırlarda ekle. Git, daha önce izlemeye başladığı dosyaları bu ayar yüzünden takipten çıkarmaz.
