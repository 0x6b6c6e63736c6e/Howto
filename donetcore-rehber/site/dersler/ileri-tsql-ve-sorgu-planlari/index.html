CTE ile doluluk ve sıralama

CTE, tek bir SQL ifadesinin içinde adlandırılmış sorgu sonucudur. Doluluk her etkinlik için kayıt sayısını hesaplar. Dış sorgu kalan yeri, doluluk yüzdesini ve DENSE_RANK ile kayıt sayısına göre sıralamayı üretir. Aynı kayıt sayısı aynı sırayı alır. LEFT JOIN kayıt almamış etkinliği de gösterir.

Rapor 1 · Doluluk sıralaması
;WITH Doluluk AS
(
    SELECT e.Id, e.Ad, e.Kontenjan, COUNT(k.KatilimciId) AS KayitSayisi
    FROM dbo.Etkinlikler AS e
    LEFT JOIN dbo.EtkinlikKayitlari AS k ON k.EtkinlikId = e.Id
    GROUP BY e.Id, e.Ad, e.Kontenjan
)
SELECT Id, Ad, Kontenjan, KayitSayisi,
       Kontenjan - KayitSayisi AS KalanYer,
       CAST(100.0 * KayitSayisi / Kontenjan AS decimal(5, 2)) AS DolulukYuzdesi,
       DENSE_RANK() OVER (ORDER BY KayitSayisi DESC) AS KayitSirasi
FROM Doluluk
ORDER BY KayitSirasi, Id;

Pencere fonksiyonlarıyla katılımcı raporu

PARTITION BY hesaplamayı her katılımcı için ayrı yapar. ROW_NUMBER etkinlikleri katılımcı içinde kimliğe göre numaralandırır. COUNT(*) OVER aynı katılımcının toplam kayıt sayısını her satırda gösterir. Bu rapor kayıtlı katılımcıları listeler.

Rapor 2 · Katılımcı kayıtları
SELECT k.Id AS KatilimciId, k.Ad AS Katilimci, e.Id AS EtkinlikId, e.Ad AS Etkinlik,
       ROW_NUMBER() OVER (PARTITION BY k.Id ORDER BY e.Id) AS Sira,
       COUNT(*) OVER (PARTITION BY k.Id) AS EtkinlikSayisi
FROM dbo.Katilimcilar AS k
JOIN dbo.EtkinlikKayitlari AS r ON r.KatilimciId = k.Id
JOIN dbo.Etkinlikler AS e ON e.Id = r.EtkinlikId
ORDER BY k.Id, e.Id;

Başlangıç verisinde Deniz, Ece ve Mert’in her biri için bir satır, sıra 1 ve etkinlik sayısı 1 görünür. Sıra kayıt tarihi değildir. Mevcut tabloda kayıt tarihi bulunmadığından etkinlik kimliği kullanılır.

Kümülatif kayıt raporu

SUM ... OVER etkinlik kimliği sırasındaki kayıt sayılarını biriktirir. ROWS UNBOUNDED PRECEDING ilk satırdan mevcut satıra kadar olan çerçeveyi açıkça tanımlar. Sonuç zaman serisi değildir, kimlik sırasına göre birikimdir.

Rapor 3 · Kümülatif kayıt
;WITH KayitOzeti AS
(
    SELECT e.Id, e.Ad, COUNT(r.KatilimciId) AS KayitSayisi
    FROM dbo.Etkinlikler AS e
    LEFT JOIN dbo.EtkinlikKayitlari AS r ON r.EtkinlikId = e.Id
    GROUP BY e.Id, e.Ad
)
SELECT Id, Ad, KayitSayisi,
       SUM(KayitSayisi) OVER (ORDER BY Id ROWS UNBOUNDED PRECEDING) AS KumulatifKayit
FROM KayitOzeti
ORDER BY Id;

Başlangıç verisinde birinci etkinlik için 3, ikinci etkinlik için de 3 kümülatif kayıt görünür.

Geçici tabloda indeks deneyi

On beşinci dersin veritabanında kayıt tablosunun birincil anahtarı (EtkinlikId, KatilimciId), ayrıca KatilimciId indeksi vardır. Bunları değiştirmeden etkinlik kontenjanı filtresi için ayrı bir deney yapacağız.

Betik etkinlikleri bağlantıya özel geçici tabloya kopyalar. İlk SELECT indeks öncesi, aynı SELECT indeks sonrası çalışır. (Kontenjan, Id) INCLUDE (Ad) filtre ve sıralama için bir adaydır. İndeksin seçilip seçilmeyeceğine SQL Server karar verir.

indeks-deneyi.sql
-- Aynı oturumda çalıştırın. #EtkinlikDeneyi oturum kapanınca silinir.
-- Mevcut kalıcı tablolara veya indekslere dokunulmaz.
DROP TABLE IF EXISTS #EtkinlikDeneyi;
CREATE TABLE #EtkinlikDeneyi
(
    Id int NOT NULL PRIMARY KEY,
    Ad nvarchar(80) NOT NULL,
    Kontenjan int NOT NULL
);
INSERT INTO #EtkinlikDeneyi (Id, Ad, Kontenjan)
SELECT Id, Ad, Kontenjan FROM dbo.Etkinlikler;

-- SSMS'te Include Actual Execution Plan seçeneğini açın.
-- Messages sekmesindeki logical reads ve süreyi kaydedin.
SET STATISTICS IO ON;
SET STATISTICS TIME ON;

SELECT Id, Ad, Kontenjan
FROM #EtkinlikDeneyi
WHERE Kontenjan >= 30
ORDER BY Kontenjan, Id;

-- Karşılaştırılacak geçici indeks
CREATE INDEX IX_Deney_Kontenjan_Id ON #EtkinlikDeneyi (Kontenjan, Id) INCLUDE (Ad);

SELECT Id, Ad, Kontenjan
FROM #EtkinlikDeneyi
WHERE Kontenjan >= 30
ORDER BY Kontenjan, Id;

SET STATISTICS TIME OFF;
SET STATISTICS IO OFF;

Az sayıdaki başlangıç verisiyle SQL Server iki durumda da tarama seçebilir. İndeks oluşturmak ve sürdürmek ek maliyet getirir. Gerçekçi veri hacmi ve iş yükünde plan ile ölçüm yapmadan kalıcı indeks kararı verme.

Gerçek sorgu planını incele

SQL Server Management Studio’da sorgu penceresinin veritabanını seç, Include Actual Execution Plan seçeneğini aç ve indeks deneyi betiğini aynı oturumda çalıştır. Execution Plan sekmesinde iki SELECT planını karşılaştır. Operatörlerde kullanılan indeks, seek veya scan, sıralama, tahmini ve gerçek satır sayılarına bak.

Messages sekmesindeki STATISTICS IO logical reads ve STATISTICS TIME CPU/geçen süre değerlerini her SELECT için ayrı kaydet. İlk ve tekrar çalıştırmalar önbellekten etkilenebilir. Gerçek plan için sorguyu çalıştırma ve ilgili veritabanlarında SHOWPLAN yetkisi gerekir.

Bu derste örnek veritabanına karşı gerçek SQL Server planı alınmadı. Kendi ölçüm sonucunu bu adımlarla oluşturabilirsin.

Betiği çalıştır ve alıştırma

On beşinci dersin SQL Server veritabanını seçip rapor betiğini çalıştır. Beklenen değerler başlangıçtaki iki etkinlik ve üç kayıt içindir. Sonradan eklenen kayıtlar sonuçları değiştirir.

Rapor betiğini indir · İndeks deneyi betiğini indir

Alıştırma olarak ikinci etkinliğe bir katılımcı kaydet ve ilk raporda doluluk sırasını tekrar incele. Gerçek planı ve logical reads değerlerini kaydet.
