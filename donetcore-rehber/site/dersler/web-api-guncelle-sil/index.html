Web API ile güncelleme ve silme

Etkinlik API’sine yönetici yetkisiyle güncelleme ve silme işlemleri ekle.

.NET 10Ders 10Yaklaşık 35 dakika
Ön koşul

Dokuzuncu dersin API ve yönetici oturumu ile SQL Server bağlantısı.

Örnek projeyi indir

Güncelleme ve silme adresleri

PUT /api/etkinlikler/{id} etkinlik adını ve kontenjanı birlikte günceller. DELETE /api/etkinlikler/{id} etkinliği siler. Her iki işlem yönetici rolü ve doğrulama belirteci gerektirir.

DurumYanıt
İşlem başarılı204 No Content
Etkinlik bulunamadı404 Not Found
Geçersiz form veya eksik belirteç400 Bad Request
Oturum yok / yönetici rolü yok401 / 403
Kontenjan kayıt sayısından az409 Conflict

Controller işlemlerini ekle

Dokuzuncu dersin controller dosyasına aşağıdaki iki action’ı ekle. [ApiController] güncelleme modelindeki ad ve kontenjan kurallarını doğrular. PUT gövdesinde iki alan da zorunludur. Kayıt sayısını aşan bir kontenjan azaltma girişimi 409 döndürür.

EtkinliklerApiController.cs · yeni action’lar
[Authorize(Roles = "Yonetici")]
    [ValidateAntiForgeryToken]
    [HttpPut("{id:int}")]
    public async Task<IActionResult> Guncelle(
        int id, [FromBody] EtkinlikFormu form, CancellationToken cancellationToken)
    {
        await using var transaction = await db.Database.BeginTransactionAsync(cancellationToken);
        var kilitlenen = await db.Etkinlikler.Where(e => e.Id == id)
            .ExecuteUpdateAsync(set => set.SetProperty(e => e.Kontenjan, e => e.Kontenjan), cancellationToken);
        if (kilitlenen == 0)
            return NotFound();

        var kayitSayisi = await db.EtkinlikKayitlari.CountAsync(k => k.EtkinlikId == id, cancellationToken);
        if (form.Kontenjan!.Value < kayitSayisi)
            return Conflict(new { mesaj = "Kontenjan mevcut kayıt sayısından az olamaz.", kayitSayisi });

        var etkinlik = await db.Etkinlikler.SingleAsync(e => e.Id == id, cancellationToken);
        etkinlik.Ad = form.Ad!;
        etkinlik.Kontenjan = form.Kontenjan.Value;
        await db.SaveChangesAsync(cancellationToken);
        await transaction.CommitAsync(cancellationToken);
        return NoContent();
    }

    [Authorize(Roles = "Yonetici")]
    [ValidateAntiForgeryToken]
    [HttpDelete("{id:int}")]
    public async Task<IActionResult> Sil(int id, CancellationToken cancellationToken)
    {
        await using var transaction = await db.Database.BeginTransactionAsync(cancellationToken);
        var kilitlenen = await db.Etkinlikler.Where(e => e.Id == id)
            .ExecuteUpdateAsync(set => set.SetProperty(e => e.Kontenjan, e => e.Kontenjan), cancellationToken);
        if (kilitlenen == 0)
            return NotFound();

        var etkinlik = await db.Etkinlikler.SingleAsync(e => e.Id == id, cancellationToken);
        db.Etkinlikler.Remove(etkinlik);
        await db.SaveChangesAsync(cancellationToken);
        await transaction.CommitAsync(cancellationToken);
        return NoContent();
    }

Transaction başındaki değişmeyen UPDATE, etkinlik satırında yazma kilidi alır. Altıncı dersteki kayıt servisi aynı satırda UPDLOCK aldığı için SQL Server’da bu işlemler sıraya girer. Kayıt sayısı kilit alındıktan sonra okunur ve değişiklik commit edilene kadar kilit tutulur. SQL Server tetikleyicileri varsa bu UPDATE onları da çalıştırabilir. Diğer yazma yolları da aynı kurala katılmalıdır.

Silme işleminde mevcut yabancı anahtarın ON DELETE CASCADE davranışı etkinliğe ait katılımcı kayıtlarını siler. Katılımcı kişileri korunur. Örneği denemek için ayrı bir geliştirici veritabanı kullan.

İstekleri dene

Örnek projeyi açıp dokuzuncu dersteki bağlantı ve yönetici hesabıyla çalıştır. Tarayıcıda yönetici girişi yaptıktan sonra aynı sitedeki geliştirici konsolunda önce güncellemeyi dene. Kimliği kendi test etkinliğine göre değiştir.

Terminal · ZIP içindeki ders klasöründen
ASPNETCORE_ENVIRONMENT=Development dotnet run --project Etkinlikler --no-launch-profile --urls http://localhost:5087
Tarayıcı konsolu · PUT
const token = (await (await fetch("/api/etkinlikler/form-belirteci")).json()).token;
const yanit = await fetch("/api/etkinlikler/2", {
  method: "PUT",
  headers: { "Content-Type": "application/json", "X-CSRF-TOKEN": token },
  body: JSON.stringify({ ad: "SQL Server Atölyesi", kontenjan: 50 })
});
console.log(yanit.status);

GET /api/etkinlikler/2 ile güncel alanları kontrol et. Daha sonra yalnızca silinmesini istediğin test etkinliğinin kimliğiyle DELETE isteğini çalıştır.

Tarayıcı konsolu · DELETE
const token = (await (await fetch("/api/etkinlikler/form-belirteci")).json()).token;
const yanit = await fetch("/api/etkinlikler/2", {
  method: "DELETE",
  headers: { "X-CSRF-TOKEN": token }
});
console.log(yanit.status);

204 yanıtı gövde içermez. Sonraki GET isteği 404 döndürür. Silme, etkinliğin ilişkili kayıtlarını da kaldırır.

Test ve alıştırma

Örnek testleri SQLite üzerinde başarılı güncelleme ve silmeyi, 400, 401, 403, 404 ve 409 yanıtlarını, kayıtların silinip katılımcıların korunmasını denetler. Eşzamanlı kayıt ile güncellemenin SQL Server kilit davranışı ayrıca SQL Server üzerinde sınanmalıdır.

Terminal
dotnet test Etkinlikler.Tests/Etkinlikler.Tests.csproj

Alıştırma olarak üç kayıtlı ilk etkinliğin kontenjanını 2’ye düşürmeyi dene. 409 yanıtındaki kayıt sayısını incele ve GET isteğiyle kontenjanın değişmediğini doğrula.
