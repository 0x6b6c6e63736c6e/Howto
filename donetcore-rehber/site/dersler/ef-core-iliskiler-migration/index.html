Etkinlik ve katılımcı ilişkisi

Bir etkinliğe birçok katılımcı, bir katılımcı da birçok etkinliğe kayıt olabilir. EtkinlikKayitlari ara tablosu iki tarafı birbirine bağlar. Her ara satır bir etkinliğe ve bir katılımcıya aittir. Böylece iki adet bire çok ilişki, birlikte çoktan çoğa kayıt ilişkisini oluşturur.

EtkinlikId ve KatilimciId yabancı anahtardır. İkisinin oluşturduğu bileşik birincil anahtar, aynı katılımcının aynı etkinliğe iki kez kaydedilmesini engeller. Mevcut yabancı anahtarların cascade davranışı etkinlik silinince ilgili kayıtları da siler.

Navigation özellikleri ve eşleme

Koleksiyonlar bir etkinliğin veya katılımcının kayıtlarına erişmeyi sağlar. Ara kayıttaki navigation özellikleri ilgili etkinliğe ve katılımcıya ulaşır. JsonIgnore, API etkinlik yanıtında kayıtların döngü oluşturmasını önler.

Models/Etkinlik.cs
using System.Text.Json.Serialization;

namespace Etkinlikler.Models;

public sealed class Etkinlik
{
    public int Id { get; set; }
    public string Ad { get; set; } = string.Empty;
    public int Kontenjan { get; set; }
    public string? Aciklama { get; set; }

    [JsonIgnore]
    public ICollection<EtkinlikKaydi> Kayitlar { get; set; } = new List<EtkinlikKaydi>();
}
Models/Katilimci.cs
namespace Etkinlikler.Models;

public sealed class Katilimci
{
    public int Id { get; set; }
    public string Ad { get; set; } = string.Empty;
    public ICollection<EtkinlikKaydi> Kayitlar { get; set; } = new List<EtkinlikKaydi>();
}
Models/EtkinlikKaydi.cs
namespace Etkinlikler.Models;

public sealed class EtkinlikKaydi
{
    public int EtkinlikId { get; set; }
    public int KatilimciId { get; set; }
    public Etkinlik Etkinlik { get; set; } = null!;
    public Katilimci Katilimci { get; set; } = null!;
}
Data/EtkinlikDbContext.cs
using Etkinlikler.Models;
using Microsoft.AspNetCore.Identity.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore;

namespace Etkinlikler.Data;

public sealed class EtkinlikDbContext(DbContextOptions<EtkinlikDbContext> options)
    : IdentityDbContext(options)
{
    public DbSet<Etkinlik> Etkinlikler => Set<Etkinlik>();

    public DbSet<EtkinlikKaydi> EtkinlikKayitlari => Set<EtkinlikKaydi>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        base.OnModelCreating(modelBuilder);
        var etkinlik = modelBuilder.Entity<Etkinlik>();

        etkinlik.ToTable("Etkinlikler", table =>
            table.HasCheckConstraint("CK_Etkinlikler_Kontenjan", "[Kontenjan] BETWEEN 1 AND 500"));

        etkinlik.Property(item => item.Ad).HasMaxLength(80).IsRequired();

        etkinlik.Property(item => item.Aciklama).HasMaxLength(150);

        etkinlik.HasData(
            new Etkinlik { Id = 1, Ad = "Web Geliştirme Atölyesi", Kontenjan = 25 },
            new Etkinlik { Id = 2, Ad = "SQL Server Semineri", Kontenjan = 40 });

        var katilimci = modelBuilder.Entity<Katilimci>();
        katilimci.ToTable("Katilimcilar");
        katilimci.Property(item => item.Ad).HasMaxLength(80).IsRequired();
        katilimci.HasData(
            new Katilimci { Id = 1, Ad = "Deniz Kaya" },
            new Katilimci { Id = 2, Ad = "Ece Arslan" },
            new Katilimci { Id = 3, Ad = "Mert Yılmaz" });

        var kayit = modelBuilder.Entity<EtkinlikKaydi>();
        kayit.ToTable("EtkinlikKayitlari");
        kayit.HasKey(item => new { item.EtkinlikId, item.KatilimciId });
        kayit.HasOne(item => item.Etkinlik).WithMany(item => item.Kayitlar).HasForeignKey(item => item.EtkinlikId);
        kayit.HasOne(item => item.Katilimci).WithMany(item => item.Kayitlar).HasForeignKey(item => item.KatilimciId);
        kayit.HasData(
            new EtkinlikKaydi { EtkinlikId = 1, KatilimciId = 1 },
            new EtkinlikKaydi { EtkinlikId = 1, KatilimciId = 2 },
            new EtkinlikKaydi { EtkinlikId = 1, KatilimciId = 3 });
    }
}

Yeni Aciklama alanı isteğe bağlı ve en fazla 150 karakterdir. Form ve API modeli aynı sınırı doğrular. PUT tüm formu günceller. Açıklama gönderilmezse açıklama alanı boşaltılır.

İlişkili kayıtları oku

Include kayıtları, ThenInclude her kaydın katılımcısını yükler. Aşağıdaki sorgu bir etkinliği ve katılımcı adlarını okur.

LINQ
var etkinlik = await db.Etkinlikler
    .AsNoTracking()
    .Include(e => e.Kayitlar)
        .ThenInclude(k => k.Katilimci)
    .SingleAsync(e => e.Id == 1);
foreach (var kayit in etkinlik.Kayitlar)
    Console.WriteLine(kayit.Katilimci.Ad);

Açıklama alanını migration ile ekle

Model değişikliğinden sonra EF Core eski snapshot ile modeli karşılaştırır. ZIP dosyasında EtkinlikAciklamasi migration’ı hazırdır. Kendi önceki ders kopyanda aynı model ve eşlemeleri yaptıysan migration’ı bir kez oluşturabilirsin.

Terminal · kendi kopyanda
dotnet ef migrations add EtkinlikAciklamasi
dotnet ef migrations script IdentityEkle EtkinlikAciklamasi -o degisiklik.sql

Oluşturulan migration’ı incele. EF’nin ürettiği başlangıç kayıtlarına yönelik gereksiz UpdateData adımları bu örnekte çıkarıldı. Yeni sütun nullable olduğu için eski satırlar NULL değerini alır. Down sütunu kaldırır ve açıklama verisini siler.

Migrations · EtkinlikAciklamasi.cs
using Microsoft.EntityFrameworkCore.Migrations;

#nullable disable

namespace Etkinlikler.Migrations
{
    /// <inheritdoc />
    public partial class EtkinlikAciklamasi : Migration
    {
        /// <inheritdoc />
        protected override void Up(MigrationBuilder migrationBuilder)
        {
            migrationBuilder.AddColumn<string>(
                name: "Aciklama",
                table: "Etkinlikler",
                type: "nvarchar(150)",
                maxLength: 150,
                nullable: true);

        }

        /// <inheritdoc />
        protected override void Down(MigrationBuilder migrationBuilder)
        {
            migrationBuilder.DropColumn(
                name: "Aciklama",
                table: "Etkinlikler");
        }
    }
}

Yedeklenmiş geliştirici veritabanında SQL’i inceledikten sonra migration’ı uygula. İlk üç migration’ın uygulandığı örnekte komut yalnızca eksik migration’ı çalıştırır.

Terminal
dotnet ef database update

Önceki ve sonraki etkinlik ve kayıt sayılarını karşılaştır. Bu örneğin migration’ı mevcut satırları güncellemez veya silmez. Canlı veritabanına uygulamadan önce yedek alıp hedef ortamda ayrıca doğrula.

Çalıştır ve doğrula

ZIP içindeki Etkinlikler klasöründe üçüncü ve on ikinci derslerdeki SQL Server ve JWT ayarlarını kullan. Önce dotnet restore ve dotnet tool restore çalıştır. Development ortamında dotnet ef database update ile migration’ları uygula. Uygulamayı çalıştırıp etkinlik ekleme formunda açıklama gir veya API POST gövdesine aciklama ekle.

Terminal · macOS ve Linux
ASPNETCORE_ENVIRONMENT=Development dotnet run --no-launch-profile --urls http://localhost:5091

PowerShell’de önce $env:ASPNETCORE_ENVIRONMENT = "Development" çalıştır ve ön eki kaldır. API GET sonucunda yeni açıklama alanını ve önceki etkinlikleri kontrol et.

Test ve alıştırma

Örnek testleri SQLite üzerinde navigation özellikleriyle üç katılımcıyı okumayı ve açıklama kaydını kontrol eder. Migration SQL’i SQL Server sağlayıcısıyla üretilip incelenmiştir. SQL Server’da migration uygulama testi ayrıca yapılmalıdır.

Terminal · ZIP içindeki ders klasöründen
dotnet test Etkinlikler.Tests/Etkinlikler.Tests.csproj

Alıştırma olarak bir katılımcının kayıtlarını Include ile yükle ve etkinlik adlarını göster. Sonra 151 karakterlik açıklamanın 400 doğrulama yanıtı verdiğini dene.
